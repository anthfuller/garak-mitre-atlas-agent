# 0.1.4: concise automatic ATLAS handoff

**Historical version 0.1.4 notes.** Procedures and validation below describe that version. Use the [current Windows install guide](install-and-verify.md) and [release record](release-v1.md) for current setup and later results. Do not apply old patch ZIPs to a current checkout.

The shared renderer now writes one mapping request, compact run facts and one line per selected response. It no longer exports full transcripts or configuration into the prompt. It asks for a technique ID, an official ATLAS link, a brief rationale and an insufficient-evidence answer where warranted.

Each evidence line includes its attempt ID/output index, original detector score/disposition, response availability, and "behavior not assessed." A short untrusted input excerpt supports investigation of the attempted technique. The renderer does not infer behavioral findings. The selection remains the first five flagged responses, otherwise the first five available responses in saved report order. Counts are read from evidence, never hardcoded to 32/0.

## Validation

68 offline tests passed on Linux. Both actual artifact-generation paths use the real renderer: a mocked scanner supplies a synthetic native report through runner completion, then the CLI regenerates from that evidence with byte-identical prompt output and no second scanner launch. Additional checks cover exact excerpt prefixes, bounds, sampling, missing outputs, unknown detector results, preservation of full saved evidence, revisions, mismatch refusal and rollback. Existing single-action menu, unattended mode and error tests passed.

Windows clipboard and Notepad behavior was tested with mocks; native Windows validation was not performed for this patch. No LLM/API scan was performed. The supplied run preview was generated by the patched renderer from the exported summary and five saved observations: 32 evaluated, zero flags. The complete native report and standalone native manifest were unavailable here, so that preview is not a native-run regeneration. The operator's regeneration command performs that reconciliation locally.
