# 0.1.4 — concise automatic ATLAS handoff

The shared renderer now writes one mapping request, compact run facts and one line per selected response. It no longer exports full transcripts or configuration into the prompt. It asks for a technique ID, an official ATLAS link, a brief rationale and an insufficient-evidence answer where warranted.

Each evidence line includes its attempt ID/output index, original detector score/disposition, response availability, and "behavior not assessed." A short untrusted input excerpt supports investigation of the attempted technique. The renderer does not infer behavioral findings. The selection remains the first five flagged responses, otherwise the first five available responses in saved report order. Counts are read from evidence, never hardcoded to 32/0.

## Apply over the existing installation

This is one cumulative source/test/documentation patch. No earlier patch ZIP needs to be reapplied. Save `Garak_Playbook_0_1_4_Fix.zip` beside the existing `garak-playbook` folder. Run in **Windows PowerShell** from that parent directory:

```powershell
Expand-Archive -LiteralPath .\Garak_Playbook_0_1_4_Fix.zip -DestinationPath . -Force -ErrorAction Stop
```

Only the files included in the ZIP are replaced. There is no package installation, configuration rewrite, model change, or scan. The ZIP excludes private configuration, campaign definitions, model data and scan evidence. It contains the complete updated runner and all matching offline tests, not a fragile line-number patch.

To rebuild a saved run's handoff, use the Python executable from the existing Garak environment. Substitute your actual paths in this **Windows PowerShell** example:

```powershell
& "C:\AI-Lab\garak-env\Scripts\python.exe" `
  "D:\AI-Lab\projects\garak-playbook\playbook.py" handoff `
  --run-dir "D:\AI-Lab\evaluations\<existing-run-folder>" --regenerate
```

Regeneration reads the original report, manifest and summary, requires matching analysis, preserves the old handoff and checksum index in `handoff-revisions`, then replaces only the derived prompt and checksum index. It does not launch Garak or change settings. Without `--regenerate`, the command displays the existing handoff without rewriting it.

The completion menu is unchanged:

```text
[1] Copy ATLAS prompt and return to PowerShell
[2] Open ATLAS prompt in Notepad and return to PowerShell
[3] Return to PowerShell
```

Both actions use the finished `atlas_handoff.md` and exit after one confirmation. Enter, 3 or Ctrl+C exits. `--yes` prints status, counts and full path without prompts or desktop actions. Editor/clipboard errors leave the recorded scan outcome unchanged.

## Validation

68 offline tests passed on Linux. Both actual artifact-generation paths use the real renderer: a mocked scanner supplies a synthetic native report through runner completion, then the CLI regenerates from that evidence with byte-identical prompt output and no second scanner launch. Additional checks cover exact excerpt prefixes, bounds, sampling, missing outputs, unknown detector results, preservation of full saved evidence, revisions, mismatch refusal and rollback. Existing single-action menu, unattended mode and error tests passed.

Windows clipboard and Notepad behavior was tested with mocks; this patch has not been executed on Windows by the builder. No LLM/API scan was performed. The supplied run preview was generated by the patched renderer from the exported summary and five saved observations: 32 evaluated, zero flags. The complete native report and standalone native manifest were unavailable here, so that preview is not a native-run regeneration. The operator's regeneration command performs that reconciliation locally.
